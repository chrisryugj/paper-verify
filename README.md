# paper-verify — 논문 인용 검증 스킬

논문·보고서에 달린 **인용(법령·판례·학술문헌·웹출처)이 진짜인지, 표기가 맞는지, 내용이 원문과 일치하는지**를 실제 원본과 대조해 검증하는 [Claude Code](https://claude.com/claude-code) 스킬.

AI로 초안을 쓰다 보면 **있지도 않은 논문을 지어내거나(환각 인용)**, 집필하는 사이 **법 조문이 개정돼 내용이 달라지거나**, 저자·연도를 잘못 적는 일이 흔하다. 이걸 사람이 일일이 원문 찾아 대조하는 게 고통스러워서 만든 도구다.

---

## ⭐ 이 도구로 할 수 있는 것 / 없는 것 (기능 명세)

가장 먼저 알아야 할 것 — **자동으로 되는 검증**과 **원문 파일을 넣어줘야 되는 검증**, 그리고 **구조적으로 안 되는 것**이 나뉜다.

### ✅ 자동으로 되는 것 (파일 하나만 주면 됨)

| 검증 | 무엇을 확인하나 | 소스 |
|------|----------------|------|
| **법령 실존·현행성** | 그 법·조문이 실제로 있는지, 개정돼서 문구가 바뀌지 않았는지, 시행일은 언제인지 | 법제처 국가법령정보센터 |
| **판례 실존** | 사건번호·법원·선고일이 맞는지, 실제 있는 판결인지 | 법제처 |
| **영문 논문 서지** | DOI가 진짜인지, 제목·저자·연도·저널이 인용 표기와 맞는지 | CrossRef · OpenAlex · Semantic Scholar |
| **국문 논문 서지** | KCI 등재 학술지논문의 실존·저자·연도·저널·논문 페이지범위 | KCI 제목검색 API |
| **학위논문 실존** | 국내 석·박사 학위논문이 실제 있는지 | RISS |
| **웹·보도자료 링크** | 링크가 살아있는지, 죽었으면 과거 기록으로 대조 | WebFetch → Wayback Machine |

즉 **"이 인용이 실존하는가 + 표기가 정확한가"** 는 논문 파일 하나만 주면 자동으로 끝난다.

### 🔍 조건부로 되는 것 — 페이지 단위 내용 검증 (전문 대조 모드)

> **"이 논문이 참고문헌의 몇 페이지부터 몇 페이지 내용을 실제로 참고했는가"** 까지 보는 기능.

단순히 "그 논문이 존재하느냐"를 넘어서, 인용이 지목한 **바로 그 페이지의 실제 내용이 논문 주장을 뒷받침하는지** 대조한다. 인용 조작·과장·페이지 오기를 잡는 가장 강력한 검증이다.

**단, 조건이 있다** — 검증하려면 그 **참고논문의 본문 PDF**가 있어야 한다. 사용자가 검증 대상 논문과 함께 참고논문 PDF들을 넣어주면 된다.

판정은 5단계:
- ✅ **뒷받침** — 지정 페이지에 그 내용이 있고 논문 서술과 일치
- ⚠️ **과장/왜곡** — 있긴 한데 논문이 원문보다 세게 주장하거나 맥락을 잘라냄
- ⚠️ **페이지 어긋남** — 내용은 그 논문에 있으나 인용이 가리킨 페이지가 틀림 (쪽 오기)
- ❌ **부재** — 지정 페이지에 그 내용이 없음 (인용 조작 의심)
- 🔍 **미검증** — 원문 PDF가 없거나, 스캔 이미지라 글자를 못 읽음

### ❌ 구조적으로 안 되는 것

| 안 되는 것 | 이유 |
|-----------|------|
| **논문만 주면 참고문헌 원문까지 자동으로 구해서 페이지 검증** | 국내 학술논문 본문은 DBpia·교보스콜라 등 **유료·로그인 벽** 뒤에 있고, KCI API도 서지+초록까지만 준다. 무료로 본문을 자동 수집할 방법이 없다 |
| **초록만 보고 페이지 내용 판단** | 초록은 요약이라 특정 페이지 내용을 대조할 수 없다 |

**정리** — 페이지 단위 내용 검증을 원하면 **참고논문 PDF를 사람이 직접 확보해 넣어주는 것이 유일한 방법**이다. 이건 도구의 한계가 아니라 국내 논문 저작권·유료화 구조 때문이다.

## 판정 등급 (서지 검증)

- ✅ **확인** — 실존 + 서지 일치
- ⚠️ **불일치** — 존재하지만 뭔가 다름(조문 개정, 연도 오기, 저자 누락, 조항번호 밀림, 상급심에서 뒤집힌 판례 등). **무엇이 어떻게 다른지 반드시 병기**
- ❌ **미확인** — 환각 의심. 단, **최소 2개 독립 소스에서 못 찾았을 때만** ❌ 처리(한 곳에서 못 찾았다고 단정하지 않음)

검증 못 한 항목(접근 불가한 소스 등)은 "미검증"으로 솔직하게 분리 보고한다. 조용히 빼먹지 않는다.

## 사용법

Claude Code에서 논문 파일(HWP·PDF·텍스트)과 함께 이렇게 말하면 된다:

```
이 논문 인용 검증해줘
참고문헌 진짜 있는 건지 확인해줘
이 조문 현행인지 봐줘
이 주장 뒷받침할 선행연구 찾아줘        ← 탐색 모드(근거 찾기)
```

**페이지 단위 내용 검증**을 하려면 참고논문 PDF를 함께 넣고:

```
이 논문 인용 검증하는데, 참고문헌 원문 PDF도 같이 넣었어.
각 인용이 지목한 페이지 내용이 실제로 맞는지까지 봐줘.
```

입력은 텍스트·마크다운·PDF를 그대로 받고, HWP는 자동으로 HWPX 변환해서 처리한다. 참고문헌 목록만 던져줘도 동작한다.

## 환경변수 설정 (없어도 기본 동작함)

| 환경변수 | 용도 | 발급 |
|----------|------|------|
| `KCI_API_KEY` | **국문 학술지논문 서지검증 주력.** KCI 제목검색(articleSearch) | https://open.kci.go.kr 무료 (호출할 서버의 **공인 IP 등록** 필요) |
| `KCI_DATA_GO_KR_KEY` | 공공데이터포털 KCI **보조** — 제목검색은 안 되고 article-id 조회·참고문헌 확장용 | https://data.go.kr 에서 KCI OpenApi 활용신청(자동승인) |
| `LAW_OC` | 법제처 직접 호출 폴백 — 평소엔 프록시라 불필요 | https://open.law.go.kr 무료 |
| `OPENALEX_MAILTO` | OpenAlex 안정 접속용 본인 이메일 | 발급 불필요 |

> ⚠️ **KCI 키는 공인 IP에 묶인다.** 신청할 때 API를 호출하는 컴퓨터의 공인 IP를 등록하는데, 인터넷 IP가 바뀌면(공유기 재부팅 등) 키가 막힌다. `401/403` 오류가 나면 KCI 마이페이지에서 현재 IP로 수정하면 된다.

발급받은 키는 `~/.zshrc`(또는 `~/.bashrc`)에 이렇게 한 줄 추가:

```bash
export KCI_API_KEY=발급받은키
```
